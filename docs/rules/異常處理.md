# 異常處理

1. **基本規範**

   - 所有異常必須被處理或聲明拋出，避免出現未處理的異常。

   - 異常處理應該有具體的處理措施，不可簡單地捕獲異常後不做任何處理。

2. **異常分類**

   - 使用自定義異常類來描述業務異常。

   - 對於系統異常，應使用標準的 Java 異常類（如 `IOException`, `SQLException`）。

3. **異常捕獲**

   - 捕獲異常時應該根據實際需要選擇具體的異常類型，避免直接捕獲 `Exception` 或 `Throwable`。

   - 捕獲異常後，應該記錄日誌或進行其他必要的處理。

4. **異常拋出**

   - 在方法中拋出異常時，應該在方法簽名中使用 `throws` 關鍵字聲明可能拋出的異常。

   - 拋出的異常信息應該詳細，包含有助於問題排查的具體信息。

5. **異常轉換**

   - 需要進行異常轉換時，應保留原始異常信息，以便追溯問題根源。

   - 使用 `throw new MyException("details", e)` 的方式將異常封裝並重新拋出。

6. **日誌記錄**

   - 捕獲異常時，應該記錄異常日誌，日誌中應包含異常的詳細信息和堆棧追蹤。

   - 使用標準的日誌框架（如 Log4j、SLF4J）進行異常日誌的記錄。

7. **資源釋放**

   - 在捕獲異常後，應該確保相關資源（如文件流、數據庫連接等）能夠正確釋放。

   - 使用 `try-with-resources` 語句或在 `finally` 塊中進行資源釋放。

8. **異常信息**

   - 異常信息應該對開發者友好，包含足夠的上下文信息，幫助排查問題。

   - 避免將敏感信息（如用戶密碼、內部系統信息）包含在異常信息中。
