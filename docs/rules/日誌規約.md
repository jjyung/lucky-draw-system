# 日誌規約

1. **基本要求**

   - 必須使用統一的日誌框架，如 Log4j、SLF4J。

   - 日誌等級按照 ERROR、WARN、INFO、DEBUG、TRACE 分級。

2. **日誌級別**

   - ERROR：記錄系統級別的錯誤信息，通常是不可恢復的錯誤。

   - WARN：記錄可能會導致系統異常的警告信息。

   - INFO：記錄系統運行的關鍵操作和狀態變化。

   - DEBUG：記錄詳細的調試信息，用於開發和測試環境。

   - TRACE：記錄更為詳細的調試信息，通常只在定位問題時使用。

3. **日誌輸出**

   - 生產環境禁止使用 DEBUG 和 TRACE 級別的日誌。

   - 日誌輸出到控制台和文件中，並根據需求配置輸出到遠程日誌服務。

4. **日誌格式**

   - 日誌格式應包括時間、日誌級別、日誌內容、引發日誌的類和方法等信息。

   - 建議使用 JSON 格式記錄日誌，以便於日誌的解析和分析。

5. **敏感信息處理**

   - 禁止在日誌中記錄敏感信息，如用戶密碼、信用卡號、身份證號等。

   - 必要時，對敏感信息進行脫敏處理後再記錄。

6. **日誌滾動**

   - 配置日誌文件滾動策略，根據文件大小或日期進行滾動。

   - 保留一定數量的歷史日誌文件，並定期清理過期日誌。

7. **異常日誌**

   - 捕獲異常時，應記錄完整的異常堆棧信息。

   - 使用 `logger.error("Error message", e)` 方式記錄異常，確保堆棧信息被記錄下來。

8. **性能考量**

   - 避免在日誌語句中進行複雜的運算或字符串拼接，使用佔位符 `{}` 進行字符串替換。

   - 控制日誌的輸出頻率，避免大量日誌輸出影響系統性能。
